# Adversarial generative-architecture acceptance cases

1. **Instance variability:** From C1-A1-Q1, generate multiple allowed data lengths and multiple distinct ones counts, requiring both possible true sender check-bit outcomes. All MUST meet the inherited <=8 full-frame manual count cap.
2. **Option position:** Different realized and approved instances MUST have different correct displayed letters; the reusable contract MUST NOT record a letter.
3. **Option semantic drift:** Keep stable option identity but change a correct proposition to a false one; schema/regex checks must not allow the original key to bind silently. Secondary semantic review or human review must block it.
4. **Benign paraphrase:** Change correct wording while retaining exact meaning; no normalized-text equality rule may force rejection on literal difference alone. Acceptance still requires review of meaning.
5. **Ambiguous alternatives:** Construct two genuinely defensible options for the actual generated conditions; reject/review rather than award credit by fixed ID.
6. **1D oracle diversity:** Receiver pass/fail computed with and without flipping the parity check bit; check total transmitted flips, not merely data flips.
7. **2D double flip:** Two distinct flipped full-block positions always trigger at least one check in the specified full construction; do not claim unique location of pair.
8. **2D rectangle:** Four-data-bit rectangle passes all full row/column checks; a different four-flip pattern is not automatically a miss.
9. **C4 group semantics:** Data-only pair with identical check signatures is invisible; different signatures are detected. Quantify over exact stated group universe.
10. **C4 Extended Abstract:** A novel case result without a general condition is insufficient for the intended EA target. A different symbolic derivation may be sufficient.
11. **Blind Judge:** Transport boundary explicitly proves no assigned treatment, Tutor dialogue, MCQ marks, past performances or private future protocol data.
12. **Actual Tutor contingency:** With two materially different learner replies to the same Guided Questioning scenario, demonstrate differing pedagogically appropriate next turns on a live model, not a scripted response list.
13. **Frozen question fidelity:** Judge gets exact seen subjective text, not authored purpose or hidden exemplar; a re-freeze cannot overwrite administered form.
14. **Review-required safety:** Uncertain semantic review or Judge uncertainty must not count as learner failure, nor trigger an invented correct index.
15. **No assessment leakage:** Question-prose compiler does not receive allocated P1/P2/P3 or Tutor history; Tutor lacks assessment keys and scenarios.
16. **Real runtime:** Docker services healthy, participant dev route used, actual persisted assessment and subjective Judge trace visible; no synthetic-only success claim.
17. **No old authority:** With v0.4 active, old v0.1/v0.3 files archived under `old/`, loader cannot accidentally import old assessment bank.
18. **Multi-run family:** Exercise each of all 64 slots over several instances; verify arithmetic when possible and manually audit sample prose/semantic validity and difficulty.

These are *acceptance conditions*, not claims that any LLM or Docker validation has already been performed in this authoring ZIP.
